# Saved owned-horse pairing

The normal management slot uses `StableBreedingPlanner.Preview` to produce an immutable quote from the current `StableSnapshot`. Its public fields contain parent command references, rejections/warnings, the 50-coin fee, conception/due dates and protected home allocations. They contain no genome, inherited outcome or diagnostic phenotype. Parent selectors use public horse summaries. Unknown ancestry stays unknown; this slice does not invent exact coat probabilities or an unrelated pedigree. The shared pedigree query retains its nullable exact coefficient and separately supplies the conservative minimum proved by recorded edges. Eligibility blocks that minimum at 1/8 even when the exact coefficient is unknown, including common named ancestors whose records are missing.

`AtomicSaveStore.CommitStableBreeding` locks and reloads the primary save before acting. It recognizes an exact recorded request first, rejects a reused command with different inputs, checks the requested save/horse/capacity revisions and derives the current hold. The hold is attached only to a transient snapshot, then the existing `ConceptionTransaction.Apply` prepares and applies the canonical conception. Publication saves the pregnancy, unborn identity, immutable evidence, one wallet debit, consumed reservation and breeding-stream position as one root. Cancellation writes nothing. An unconfirmed publication is retried with the same request, including its IDs and revisions.

The fixed four-place prototype counts each canonical owned horse once, including unborn and growing offspring, plus each unrelated pending hold. Its commitment protects one future home for the proposed foal across pregnancy, foal, youngster and adult windows. Historical child reservations are not counted in addition to their canonical child. This conservative protection does not model building upgrades, sales, leases, construction or nursing-family stall occupancy; unsupported population/capacity data is a visible block.

The original two non-breeding starters are upgraded by `EnableStarterBreeding` under the same store lock. Exact original appearance-seed markers identify the mare and stallion even after renaming. The marker is idempotent and the prior primary becomes the verified backup. Only eligibility roles and a mature starter age baseline change; no birth day, DNA, pedigree, wallet, care, calendar or RNG is fabricated. A fresh normal stable already has those roles and marker. Ambiguous records are left intact with an explanation.

`stable.text-breeding.v1` is explicitly restricted to the existing text-only Sandbox build and supported calendar/genetics. Exhaustive genetic closure remains required; matrix release checks remain the default for ordinary conception and presentation. The internal unapproved matrix used by the text planner grants no visual support. D-006 records this bounded exception, and horse rendering/animation inputs remain frozen.

Birth, naming, recovery and growth then use the same End Day and rename transactions described in `lifecycle_model.md`. The separate foaling demo is retained for its original committed-conception playtest. See `PLAYTEST.md` for the normal saved-stable flow and `STATUS.md` for actual validation.
