# Stable calendar and daily care prototype

The stable day service is a deterministic domain transaction. `StableDayService.Preview(snapshot, carePlan)` has no disk writes, random draws, or state mutation. It previews exactly one day; `AtomicSaveStore.CommitEndDay` repeats the checks under the save lock, publishes the combined result atomically, and returns the durable receipt. Retrying the same operation ID and identical request returns that receipt before checking stale revisions. Reusing the ID for different inputs is rejected.

Calendar days are zero-based in saves and each season has 28 days. The current supported profile is `calendar.v1`; daily costs and rules are `stable.dailycare.v1`. EndDay advances the calendar and each horse's age counter by one day without changing its life stage. Unknown calendar or care-policy versions are rejected.

Every player-owned horse in the active stable that is born needs an explicit assignment with feeding and bedding enabled. Those basic needs cannot be disabled. Each costs 6 coins per horse per day, plus 24 coins per day for stable operations whenever at least one eligible horse is present. Cooperative, institutional, and unborn horses are excluded from this prototype's player charges. If the wallet cannot cover the day's total, the wallet is debited only down to zero and a daily receipt records the assistance covering the shortfall. No debt, starvation, or horse removal is created. Purchased care is consumed daily; this first slice does not implement an item inventory.

Turnout and grooming are optional. Unselected care receives a small baseline recovery; selecting it adds a modest deterministic improvement. Nutrition, bedding, turnout, and grooming are stored as integer values from 0 to 10000 (10000 means 100%). Missing care records use initial values of 7000, 7000, 5000, and 5000 respectively. Existing canonical horse records remain authoritative for identity, genetics, knowledge, training, and RNG streams. Daily care is a separate `StableDailyState` root keyed by horse ID.

The service refuses to advance when an unborn horse would reach its recorded planned birth day. A foal whose next day would reach actual birth day +3, or a youngster whose next day would reach actual birth day +6, is also blocked until birth and growth processing exists. Juveniles without a recorded birth day are blocked rather than assigned an invented age anchor. Companion/NPC lifecycle automation and training, readiness, injury, fatigue, race, and breeding effects are outside this prototype; daily care does not claim those systems advance.

Save wire/schema version 2 adds the daily-care root and receipts. The decoder recognizes genuine wire/schema v1 saves and migrates them by preserving all existing records and history, adding initial care values for saved horses, and an empty EndDay receipt list. It records `stable.daily-care-root.v1-to-v2`. Unsupported earlier versions still require an explicit migration. Generic snapshot saves must preserve the calendar and daily-care history; only the validated EndDay transaction advances them.
