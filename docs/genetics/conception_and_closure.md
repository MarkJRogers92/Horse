# P1-07 — catalog closure and minimal conception API

## All-generation coat guard
The source catalog is every authoritative horse that may contribute to the live population, including founders, NPC stock and breeding-service sources. For each phased block, LiveCatalogCoatGuard repeatedly adds all nonzero-probability recombinants until the haplotype pool reaches a fixed point. It then checks the full cross-block Cartesian product of biological diplotypes against the existing phenotype resolver and release matrix. This is a conservative superset: it may block combinations that a particular pedigree/sex policy would prevent, but cannot approve a catalog merely because its immediate F1 looks supported.

Synthetic block recombination is validated too. The cross-block COAT proof factors those markers out only under the pinned core model and phenotype.v1, which make synthetic traits independent of coat classification. This does not certify extreme body meshes, tack fit or art quality. Enumeration limits, unknown versions, missing recombinants and an empty catalog fail closed. A sampled check is never a reachability certificate. No catalog or matrix class is enabled by these tests.

## Minimal conception command
ConceptionService.Prepare takes the real save header and complete authoritative horse snapshots, a trusted confirmed capacity hold, authoritative coin balance, versioned game terms and a request containing typed identities and expected revisions. It checks owned-parent authority, terms, funds, all relevant revisions, reproductive eligibility, full pedigree policy, capacity windows through adulthood, versions and the catalog closure before any offspring sampling. External studs remain explicitly blocked until the P2 authorization adapter exists.

The next event index is one-based and equals the advanced breeding stream counter. The seed comes from the save's breeding stream and index, not a request ID, UI preview, forecast or clock. Changing a rejected request ID therefore cannot reroll the next foal. The actual shared meiosis service supplies gametes/provenance; fixed development and appearance derive from labeled substreams. Child identity and cost transaction identity derive from the save identity and event index. A fresh unborn HorseRecord and existing BreedingCommit are produced once, together with the pregnant-mare replacement snapshot.

PreparedConception is an immutable proposal, NOT evidence of durability. It retains historical parent/unborn snapshots so later save/load does not try to reconstruct original parent revisions from mutable current horses. P1-09 must atomically store the receipt, debit, capacity record, unborn horse, maternal pregnancy and stream advance, and must return the same stored receipt on an identical retry before checking stale preconditions.

The capacity input is a trusted confirmed reservation projection; this does not claim a full building/calendar capacity manager. The versioned fee is trusted game configuration, not a player-entered price. Those adapters and external-stud/pregnancy UI are later tasks. The STATUS-authorized conception extension uses src/Cloverbrook.Domain/Breeding/Commit; all forecast/closure work stays in the mapped Forecasts paths. No frozen handoff edits.
